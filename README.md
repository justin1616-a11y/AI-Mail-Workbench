# AI邮件工作台 for SJTUer（SJTU Mail Workbench）

> 一个跑在你自己电脑上的邮箱整理工具。把堆满未读的收件箱，变成「待我处理 / 等待对方回复 / AI 草稿」这样的工作视图。
>
> **所有数据留在本机，不上传任何服务器。**
>
> 适配上海交通大学邮箱（`@sjtu.edu.cn`），也支持其他标准 IMAP 邮箱。

---

## 一、它解决什么问题

高校师生的邮箱有个共同特点：**每天被大量"看起来重要、其实不用回"的邮件淹没**。

- 科研管理部门、基金委的**群发申报指南通知**，一天好几封，每封都像待办
- 会议邀请、报销流水、图书馆提醒、系统通告……都在抢你的注意力
- 真正需要你动手回的那两三封，反而被埋在最下面
- 有些邮件你回了，过两周忘了对方还没回；有些邮件放太久，想起来已经过期

结果是：**你每天花在"扫邮件"上的时间，远超真正处理邮件的时间。**

这个工具做的事，就是把这些邮件**按「球在谁那边」重新分堆**：

| 工作视图 | 含义 | 你要做什么 |
|---|---|---|
| **待我处理** | 球在你这边，需要你看或回 | 一件一件处理掉 |
| **等待对方回复** | 你已经回了，等对方回音 | 不用管，超期会自动沉底 |
| **AI 草稿** | 需要你审核的回复草稿 | 读一遍、改一改、决定发不发 |
| **已延后** | 你让它过几天再出现 | 到点自己回来 |
| **今天完成** | 今天处理掉的 | 给自己一点正反馈 |
| **仅知会** | 群发通知类，不占你的待办 | 想查的时候能查到 |

**关键是最后一条**：那些"看一眼就知道不用回"的群发通知，**不再占用你的待办计数**。

## 二、功能一览

### 1. 工作桶视图

打开就是上面那张表。默认只看「待我处理」——**其他栏是信息，不是待办。**

### 2. 邮件分类与降噪

内置了一套**按高校场景配好的规则**，自动识别：

- 群发通知（申报指南、系统通告、节日问候）→ 归入「仅知会」，不占待办
- 需要你动手的（人员信息核查、结题验收、答辩安排、合作意向）→ 留在「待我处理」
- 系统类（应去业务系统办理的）→ 单独归类，不混在待回邮件里

规则可以自己改关键词，改完刷新页面生效。

### 3. 回复草稿

两种方式，按需要选：

| 方式 | 速度 | 适合什么 |
|---|---|---|
| **⚡ 快速草稿** | **立刻**（本地模板，不联网、不调模型） | 事务性回复：收到确认、婉拒、索取材料、确认时间、致谢 |
| **✎ AI 起草** | 需要几十秒 | 需要读懂并组织信息的回复 |

**快速草稿**给出的是可直接使用的中文公文腔草稿，涉及事实的地方（名额、日期、金额）
会留成 `[请补充：…]`，**不会替你编造**。想换一个模板，点一下即可。

**AI 起草**会读完整线程上下文再写。如果遇到"只有你本人能回答"的问题
（比如"课题组还有名额吗"），它会**停下来问你**，而不是编一个答案。

### 4. 发送必须两步

任何邮件发出前都要：

1. 点「确认发送」→ 生成一次性令牌
2. 点「真正发送」→ 才真的投递

**这是刻意设计**：防止误点、防止自动化程序替你发信。**工具永远不会自动发送任何邮件。**

### 5. 批量操作

勾选多封邮件，一键归档 / 标已读 / 加星 / 删除 / 设为等待。支持整批撤销。

### 6. 与 Foxmail 共存

如果你本机装了 Foxmail，工具会直接读取它的**本地索引**来导入历史邮件 ——
毫秒级，不需要重新下载几万封邮件。两个软件读同一份数据，互不干扰。

## 三、隐私与安全（请先读这一节）

**这类工具最该被问的就是这个问题，所以写在前面。**

| 问题 | 回答 |
|---|---|
| 我的邮件内容会被上传吗？ | **不会。** 邮件正文、附件、草稿全部存在你自己电脑上的 SQLite 数据库与文件里。 |
| 我的邮箱密码存在哪？ | 存在 `C:\Users\<你的用户名>\.workbuddy\secrets\` 下，**不在项目目录里**。只有你自己可读。 |
| 它会自动发邮件吗？ | **不会。** 代码层面只允许 `approved` 状态出站，而这个状态必须由你亲手点两次才能到达。 |
| AI 会读我所有邮件吗？ | **不会。** 只有在**你点了起草按钮**时，才会把那一封邮件及其线程上下文交给 AI。 |
| 会删我的邮件吗？ | 删除是**移到 Trash**，且可撤销。不做永久删除。 |
| 会不会误杀重要邮件？ | 降噪规则有"保命词"机制 —— 命中「人员信息核查」「结题验收」「答辩」等关键词的邮件**一律不降级**。 |
| 怎么彻底卸载？ | 删掉代码目录即可；再删 `~/.workbuddy/secrets/mail.cred` 清除凭据。 |

> **一句话**：这是一个**本地工具**，不是云服务。它唯一的对外网络行为是
> 连接你自己的邮箱服务器（IMAP 收信 / SMTP 发信）。

## 四、安装

### 前提

- Windows 电脑（当前版本仅支持 Windows）
- 已安装 **WorkBuddy**（本工具会复用它内置的 Python，不需要你另外装）

### 方式一：从 WorkBuddy 技能市场安装（推荐）

1. 打开 WorkBuddy，进入「技能」面板
2. 选择「添加技能 → 从 GitHub 导入」，粘贴本仓库地址
3. 安装完成后，在对话框里说：**「安装邮件工作台」**
4. 按提示完成配置（见下方"配置向导"）

### 方式二：手动下载

1. 下载本仓库（`Code → Download ZIP`）并解压到任意目录
2. 双击目录里的 **`install.cmd`**

### 配置向导会问你什么

| 步骤 | 说明 |
|---|---|
| 1. 探测邮箱 | 自动找本机 Foxmail 索引，并尝试从路径猜出你的邮箱地址 |
| 2. 填邮箱 | 你的 `@sjtu.edu.cn` 邮箱地址 |
| 3. 填密码 | **不是登录密码**，是 **IMAP/SMTP 授权码**（学校邮箱设置里生成） |
| 4. 验证 | **当场测试能不能登录**，不通会立刻告诉你 |
| 5. 可选 | 创建桌面图标 / 设置开机自启 |

> ⚠️ **关于授权码**：多数高校邮箱要求使用独立的"客户端授权码"而不是登录密码。
> 请先登录学校邮箱网页版 → 设置 → 找到「IMAP/SMTP 服务」→ 开启并生成授权码。
> 如果学校邮箱不支持 IMAP，本工具无法使用（这是邮箱服务端的限制）。

## 五、日常使用

### 启动

双击 **`启动V2工作台.cmd`**，浏览器会自动打开 `http://127.0.0.1:8080/workbench`。

（已在运行时不会重复启动，直接打开页面。）

### 每天的工作流

1. 打开「待我处理」——**只处理这一栏**
2. 需要回的：
   - 事务性的 → 点「⚡ 快速草稿」，改掉 `[请补充：…]`，点两步发送
   - 需要斟酌的 → 点「✎ AI 起草」，等草稿进「AI 草稿」栏再处理
3. 不需要回的 → 点「完成」或「归档」，它会离开待办
4. 晚点再看的 → 点「延后」，到点自己回来

**处理完就关掉**。其他栏不用管。

### 快捷键

| 键 | 动作 |
|---|---|
| `j` / `k` | 上下移动 |
| `Enter` | 打开邮件 |
| `r` | AI 起草回复 |
| `a` | 归档 |
| `s` | 延后 |
| `d` | 完成 |
| `w` | 标记为等待对方回复 |
| `/` | 搜索 |

## 六、常见问题

**Q：打开页面显示"无法访问"？**
服务没起来。看代码目录下的 `_launch.log` / `_watchdog.log` / `_server.log`。
如果这三个文件都没新内容，多半是 Python 解释器不对，重跑 `install.cmd`。

**Q：页面报 502，但服务明明在跑？**
本机设了系统代理，把 `127.0.0.1` 的请求也接走了。
检查系统代理设置，把 `127.0.0.1` 加入例外（`no_proxy`）。

**Q：我的学校邮箱不支持 IMAP 怎么办？**
暂时无解 —— 本工具依赖 IMAP 协议。可以用 Foxmail 客户端先确认你的邮箱是否支持。

**Q：需要一直开着电脑吗？**
不需要。工具按需启动，关掉电脑就是关掉它。

**Q：会占多少资源？**
常驻内存约 50 MB，空闲时不消耗 CPU（IMAP IDLE 事件驱动，不做轮询）。

**Q：我的邮箱有 4 万封邮件，能扛住吗？**
可以。实测 4 万封邮件的库，页面加载在 1 秒内。历史邮件通过 Foxmail 本地索引导入，
不需要重新下载。

**Q：升级怎么办？**
重新导入一次技能 / 覆盖代码目录即可。你的数据（`config.json` 与数据库）不受影响。

## 七、技术信息

给想了解实现或参与改进的人：

- **技术栈**：Python 3.8+（仅标准库） + 原生 HTML/JS + SQLite
- **无第三方依赖**：不需要 pip install 任何东西
- **架构**：本地 HTTP 服务（`127.0.0.1:8080`）+ 工作桶计算 + 草稿队列
- **邮件协议**：IMAP（含 IDLE 事件驱动同步）/ SMTP
- **AI 集成**：通过"草稿队列 + Worker 契约"解耦，AI 只负责理解与写作，
  状态机与发送门禁由本地服务强制执行

详见 `INSTALL.md` 与 `docs/`。
